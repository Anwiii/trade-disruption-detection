# Big Data-Driven Detection of International Trade Disruptions

A Big Data pipeline (Hadoop HDFS + Apache Spark) that detects and characterizes disruptions in international trade using UN Comtrade data, with GDELT as an auxiliary source of real-world events.

- **Data:** monthly, HS 4-digit trade records, 25 countries, 12 commodities, 2017-2025 (about 5.1 million records, 1.4 GB)
- **Method:** log-linear trend baseline per country-commodity-flow series, z-score anomaly detection, per-series Isolation Forest
- **Russia/Belarus:** both stopped reporting after 2022, so their trade is reconstructed from partner countries' records (mirror statistics)
- **Context:** GDELT event categories that spiked around each anomaly are shown as *potentially related events* (timing overlap, not proof of cause)
- **Tool:** a Streamlit dashboard where you pick an event (or any date), country and commodity

## Pipeline

```
UN Comtrade API -> per-country CSVs -> merged CSV -> HDFS -> Spark aggregation
    -> monthly series -> trend baseline + z-score + Isolation Forest
    -> ranking / charts / early-warning test / GDELT correlation -> dashboard
```

## Data is not included

The merged dataset is 1.4 GB, which is over GitHub's file limit, and the raw API output is regenerated by the scripts. To reproduce:

1. Create a free account at comtradeplus.un.org and generate an API key.
2. Set it as an environment variable (never put it in the code):
   - PowerShell: `$env:COMTRADE_KEY="your-key"`
3. Run the extraction scripts below. The free tier allows 500 calls per day.

GDELT: run `gdelt_query.sql` in the BigQuery sandbox (free, no card needed) and save the result as `gdelt_monthly_events.csv`.

## Requirements

- Hadoop 3.3.6 (run with Java 11)
- Apache Spark 4.2.0 / PySpark (run with Java 17)
- Python 3.11
- `pip install -r requirements.txt`

Hadoop and Spark need different Java versions, so use separate terminals with `JAVA_HOME` set for each.

## Run order

| Step | Script | Notes |
|---|---|---|
| 1 | `extract_trade_data_batched.py` | Pulls data from the Comtrade API. Resumable; rerun daily until it reports completion |
| 2 | `cleanup_progress_batched.py` | Run after any run that printed connection errors |
| 3 | `merge_data.py` | Combines the per-file CSVs into `trade_data_final_merged.csv` |
| 4 | `hdfs dfs -put trade_data_final_merged.csv /trade_data/` | Hadoop terminal (Java 11), daemons running |
| 5 | `extract_mirror_data.py` | Spark: filters records where Russia/Belarus are the partner |
| 6 | `audit_trade_data.py` | Spark: schema, row counts, missing values |
| 7 | `prepare_monthly_data.py` | Spark: aggregates to monthly series and caches locally |
| 8 | `analyze_trade_disruption_v2.py`, `analyze_mirror_disruption.py` | Full-dataset and mirror analyses |
| 9 | `analyze_event.py` or `event_menu.py` | Analyze any event date |
| 10 | `explain_anomalies.py` | Links anomalies to GDELT event spikes |
| 11 | `test_early_warning.py` | Tests for anomalies before an event's official date |
| 12 | `plot_summary.py` | Generates the report charts |
| 13 | `streamlit run dashboard.py` | Interactive dashboard |

Steps 8 onward use the local cache files and do not need Spark or HDFS.

## Key findings

- The method correctly flags the documented disruptions around the 2022 Russia-Ukraine war (Belarus and Russia trade) and the 2020 COVID-19 wheat export restrictions (Russia, Kazakhstan), using the same unmodified pipeline.
- Across the full dataset, the trend-adjusted z-score method reached precision 0.106, recall 0.480, F1 0.174 against a Russia/Belarus proxy label.
- Belarus energy exports show a strong anomaly in January 2022, before the invasion. This probably reflects separate EU sanctions on Belarus in 2021 rather than the war itself.
- GDELT correlation is strong for conflict and sanctions events and weak for pandemic-related policy.

## Limitations

- The precision/recall ground truth is a proxy, not hand-labeled data.
- The trend baseline needs at least about two years of pre-event history; with shorter history it extrapolates badly.
- Countries that stop reporting (Belarus after 2022, China in 2025, Bangladesh throughout) appear as anomalies. The tool detects that something changed, not why.
- Months with no reported trade are filled with zero, which is an assumption.
